## 1. 총평

개인용 도구로서의 완성도와 상용 제품으로서의 준비도를 분리해서 본다.

**개인용**: MVP 100%, 철학("비춰주는 거울") 일관 구현, 배포 운영 중. 목적 달성 상태.

**상용 관점**: 기능은 충분하나, 제품을 타인에게 파는 데 필요한 세 축이 0에 가깝다.

| 축 | 현재 | 근거 (2026-07-20 코드 확인) |
|----|------|------|
| ① 신뢰 인프라 — 타인의 돈 데이터를 잃지 않는 장치 | 없음 | IndexedDB 단독 저장, 자동 백업 없음 (수동 내보내기만) |
| ② 학습 루프 — 누가 무엇을 쓰는지 측정 | 없음 | analytics·에러 추적 라이브러리 0건 |
| ③ 지불 장치 — 결제·유료 경계 | 없음 | PRD 리스크 표에도 "수익모델 부재" 명시 |

코드 규모: 114개 TS/TSX 파일, 27,276 LOC, **테스트 파일 0개** (Vitest 설정만 존재), i18n 미도입.

핵심 판단 두 가지:

1. **상용화의 관문은 기능 추가가 아니라 신뢰·측정·결제 인프라다.** 기능 축은 이미 경쟁 수준 이상.
2. **유료화보다 "타인 리텐션 검증"이 먼저다.** 현재 만족도 데이터는 n=1(제작자 본인). PRD의 D1 60% / D7 40% 목표는 아직 한 번도 측정된 적 없다.

## 2. 상용 관점 갭 분석

| 영역 | 현재 | 상용 기준 | 심각도 |
|------|------|----------|--------|
| 데이터 안전 | 로컬 단독, 기기 분실 = 전체 유실 | 자동 백업 + 복원 + 기기 이전 | 🔴 유료 사용자 데이터 유실 = 환불 + 평판 붕괴 |
| 품질 안전망 | 테스트 0개 | 돈 계산 로직 회귀 방지 | 🔴 결제 도입 전 필수 (#127 같은 버그가 유료 사용자에게 터지면 치명적) |
| 관측 | 없음 | 에러 추적 + 익명 사용 통계 | 🔴 유료 경계 설계 자체가 불가능 |
| 발견성 | PWA 단독 (URL 직접 접근) | 앱스토어 존재 = 검색 유입 | 🟡 기존 로드맵 Phase 2와 일치 |
| 운영·법무 | 없음 | 개인정보처리방침·약관·지원 채널·(수익 시) 사업자 등록 | 🟡 동기화/결제 도입 시점에 필수화 |
| 신규 사용자 가치 증명 | 본인 최적화 | 외부 사용자 D1/D7 실측 | 🔴 BM 논의의 선행 조건 |

**local-first의 양면성**: 차별화 포인트 #3("데이터가 기기를 떠나지 않음")이 동시에 상용화 최대 리스크(PRD 리스크 표 1행 "데이터 유실")다. 이 긴장을 푸는 설계 — **opt-in 암호화 백업/동기화** — 가 상용화의 중심 과제이며, 그 자체가 가장 자연스러운 과금 지점이 된다.

## 3. BM 제언

### 3.1 전제: 철학과 BM의 정합성

| BM | 판정 | 이유 |
|----|------|------|
| 광고 | ❌ 배제 | "일상앱·무판단" 철학과 정면 충돌. 가계부 지면에 소비 유도 광고 = 이해상충 |
| 계좌연동(마이데이터) 기반 | ❌ 배제 유지 | 한국 마이데이터는 허가제 + 자본 요건 → 1인 운영 불가. 기존 "하지 않을 것" 판단 타당 |
| 사용자 직접 지불 | ✅ | "사용자에게만 책임지는 구조" — 철학과 정합. 광고 기반 무료 앱의 지속성 리스크 대비 안정적 |

### 3.2 옵션 비교

**옵션 A — 무료(로컬 완결) + 편의 구독** ← 권장

- 무료: 현재 기능 전부. 로컬에서 완결 (철학 유지, 확산 엔진)
- 유료(구독): ① 클라우드 백업/멀티기기 동기화 ② iOS 위젯 ③ 고급 리포트·테마(선택)
- 구독인 이유: 동기화는 지속적 서버 원가가 발생 → 원가 구조와 과금 구조 일치
- 기술 경로: **Dexie Cloud** — 이미 dexie 스택이라 정합. free tier(3 users/100MB)로 검증, production €0.12/user/월 수준. 1인 운영에 백엔드 구축 없이 동기화 가능
  - 대안: 자체 서버(운영 부담 → 비권장), iCloud 문서 백업(Capacitor 후 가능하나 동기화는 아님)

**옵션 B — 일회성 구매(lifetime)**

- 로컬 전용 프리미엄(고급 리포트·테마·앱 잠금)만 일회성 ₩8,000~12,000 / $6~10
- 장점: 구독 피로 회피 정서에 부합(글로벌에서 YNAB $109/yr 인상 반발 확인됨), 서버 원가 없음
- 단점: 반복 수익 없음, 동기화를 담을 수 없음
- 절충: **A+B 혼합** — 일회성 "Pro"(로컬 기능) + 구독 "Sync"(동기화만). 단, 1인 운영에서 SKU 2개 관리 부담

**옵션 C — 후원(BMC, GitHub Sponsors)**: 무료 확산기에 병행 가능하나 본 BM으로는 부족.

### 3.3 가격 벤치마크 (2026-07 검색 기준, 미국 검색엔진 결과라 국내 가격은 출시 전 재확인 필요)

| 서비스 | 가격 | 모델 |
|--------|------|------|
| 편한가계부 (한국) | 월 2,900원 / 연 24,000원 | 구독 |
| 편한가계부 Money Manager (글로벌) | ~$10 | 일회성 광고제거 |
| 뱅크샐러드 프리미엄 | 월 9,900원 | 구독 (연동 기반) |
| Buddy | $9.99/월, $49.99/연 | 구독 |
| YNAB | $109/연 | 구독 (고가 반발 존재) |
| 인디 대안 (SenticMoney 등) | ~$39/연 | 구독 |

**제안 구간**: 한국 연 15,000~24,000원 (월 1,900~2,900원), 글로벌 $15~25/yr. 자동연동이 없으므로 뱅크샐러드보다 낮게, 동기화+위젯을 담으므로 "커피 한두 잔" 프레임.

**기대치 관리 (1인 운영 손익 감각)**: 유틸리티 앱 통상 유료 전환율 2~5% 가정 시, MAU 5,000 × 3% × 연 20,000원 ≈ **연 300만원**. 수익의 병목은 가격이 아니라 MAU와 리텐션이다. 이 계산이 Track 0(검증)을 최우선에 두는 이유.

### 3.4 결제 채널

| 채널 | 수단 | 수수료 |
|------|------|--------|
| 웹(PWA) | Merchant of Record (Lemon Squeezy ~5%+$0.50, Paddle 등) | 세금 처리 대행 — 1인 글로벌 판매에 적합 |
| iOS | IAP (디지털 재화라 필수) + Small Business Program | 15% (연 수익 $1M 미만) |

앱→웹 결제 링크는 2025년 이후 (특히 미국) 완화 흐름이나 심사 리스크가 남아 있어, 초기에는 iOS IAP 단순 경로를 권장.

### 3.5 포지셔닝

**한국**: 자동연동 진영(뱅크샐러드·토스, 무료~9,900원)과 정면 경쟁 회피. 수동 기록을 "제약"이 아닌 "선택"으로 언어화 — "연동 없이, 판단 없이, 확인만". 기록 중심의 편한가계부와도 각이 다름(확인 중심).

**글로벌**: YNAB 가격 인상 반발 + no-bank-login/privacy 수요가 확인된 시장. 단 Actual Budget, BudgetVault 등 무료·오픈소스 대안이 이미 존재 → 경쟁 축은 가격이 아니라 **모바일 UX 완성도 + 감정 설계**. 태그라인 방향: *"The budget app that never judges. No bank login. No account."*

## 4. 개발 방향 (할 일 단위 · 선후관계)

### Track 0 — 검증 (모든 유료화의 선행 조건)

- [ ] 에러 추적 도입 (Sentry류)
- [ ] 익명 사용 측정 도입 — 철학상 opt-in/고지 명확히 (privacy-friendly: Plausible류 or 자체 이벤트)
- [ ] 외부 사용자 10~30명 확보 → D1/D7 리텐션, 기록 지속률 실측
- **결과물**: "타인도 남는가" 데이터. 미달이면 BM보다 습관 형성 장치(위젯·알림)에 선투자

### Track 1 — 신뢰 인프라 (유료화 전제, Track 0과 병행 가능)

- [ ] 자동 로컬 백업 + 복원 UI (ROADMAP 2.3 "선택" → **"필수" 승격** 제안)
- [ ] 클라우드 백업/동기화 PoC (Dexie Cloud free tier) → 계정·암호화 UX 검증
- [ ] 카테고리/수단 삭제 시 거래 처리 정책 + 데이터 마이그레이션 체계
- **결과물**: "기기를 바꿔도 잃지 않는다" 보장

### Track 2 — 품질·운영 (결제 도입 전 완료)

- [ ] 돈 계산 핵심 로직 테스트 — 예산 잔액, 반복거래 catch-up, 월 경계(startDayOfMonth), 할부 분할 (#127 재발 방지 장치)
- [ ] 개인정보처리방침·약관 (동기화 도입 시점부터 법적 필수)
- [ ] 지원 채널 (이메일/폼) + 환불 정책
- [ ] 접근성 개선 (ROADMAP 기술부채 — App Store 심사 대비)

### Track 3 — 채널 (기존 ROADMAP 유지, Track 1 이후 유료 기능 탑재)

- [ ] Capacitor iOS 전환 + App Store 출시 (ROADMAP 4.1)
- [ ] **iOS 위젯** — 이 앱에서 위젯은 부가기능이 아니라 "1초 확인"의 최종형이자 핵심 유료 훅
- [ ] i18n 영어 우선 (ROADMAP 3.3) → 일본어
- [ ] 포지셔닝 랜딩 페이지 (글로벌: privacy 축, 한국: 무판단 축)

### Track 4 — 수익화 실행 (Track 0·1·2 완료 후)

- [ ] 유료 경계 확정 (Track 0 데이터 기반)
- [ ] 결제 연동 (iOS IAP → 웹 MoR 순)
- [ ] 지역별 가격 실험

### 의사결정 지점

| ID | 결정 | 선택지와 영향 |
|----|------|--------------|
| D1 | 동기화 백엔드 | Dexie Cloud(빠름, 종속성) vs 자체 구축(통제, 1인 운영 부담) — PoC 후 결정 |
| D2 | 과금 구조 | 구독 단독(단순) vs 일회성+구독 혼합(구독 거부층 포섭, SKU 2개 부담) |
| D3 | 출시 순서 | 한국·글로벌 동시(리소스 분산) vs 영어권 우선(privacy 수요 확인됨, i18n 선행 필요) |

## 5. 철학과의 충돌 관리

**유지**: 무광고, 무판단 메시지, 비교 배제, local-first(동기화는 어디까지나 opt-in).

**"하지 않을 것" 재검토 기준선**: "사용자 행동을 평가·유도하는가"로 판별.

- AI 지출 **조언** → 배제 유지 (판단 행위)
- 카테고리 **자동 분류** 등 판단 없는 자동화 → 철학과 충돌하지 않음, 재검토 가능

**유료화 자체의 철학 정합**: 사용자에게 직접 과금 = 사용자 외 누구에게도 데이터·주의를 팔지 않는 구조. 랜딩 페이지에서 이 연결을 명시적으로 서사화할 것.

## 6. 한 장 요약

```
현재      : 개인용으로 완결. 상용 기준 신뢰·측정·결제 = 0
첫 단추   : 측정 도입 + 외부 사용자 리텐션 실측 (n=1 탈피)
BM        : 무료(로컬 완결) + 구독(동기화·위젯) 권장 / 일회성 혼합 대안
가격      : 한국 연 15,000~24,000원 · 글로벌 $15~25
순서      : 검증 → 신뢰 인프라 → 품질·법무 → iOS 채널 → 결제
지킬 것   : 무광고 · 무판단 · local-first (opt-in 동기화)
현실 감각 : MAU 5,000 도달 전 수익은 연 수백만원 수준 — 병목은 가격이 아니라 리텐션과 채널
```
