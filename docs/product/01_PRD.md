## 1. 개요

### 한 줄 정의

**지출 기록이 아니라 "얼마나 남았는지"를 1초 만에 비춰주는 개인 예산 관리 PWA**
— "기록하는 가계부가 아니라, 비춰주는 거울"

### 제품 목표

사용자가 앱을 여는 즉시(1초) 이번 달 남은 돈과 오늘 쓸 수 있는 돈을 확인하고, 3터치 이내로 거래를 기록하며, 판단이나 죄책감 없이 자신의 소비 패턴(=관심사)을 인식하게 한다. 절약 강요가 아닌 **인식(awareness)** 을 제공하는 것이 목표다.

### 배경

기존 가계부 앱은 지출 기록·분석 중심으로 기능이 많고 복잡하며, "지출 초과" 경고로 죄책감을 유발해 사용자가 설치 후 금방 이탈한다. PinPig는 핵심 질문을 "얼마나 썼지?"에서 **"얼마나 남았지?"** 로 전환한 MoneyMirror 기획에서 출발했다.

| 기존 가계부 | PinPig |
|------------|--------|
| "얼마나 썼지?" | **"얼마나 남았지?"** |
| 지출 = 죄책감 | 소비 = 관심의 표현 |
| 과거 기록 | 현재 상태 |
| 분석 중심 | 확인 중심 |
| 금융앱 느낌 | 노트앱 느낌 |

## 2. 타겟 사용자

### 페르소나: 김지원 (29세, IT 회사 마케터)

- **수입**: 월급 300만원 (25일 입금)
- **고정지출**: 월세 60만 · 통신비 7만 · 구독료 3만
- **행동 특성**:
  - 가계부 앱 3개 설치했다가 복잡해서 모두 삭제한 경험
  - 월말이면 "돈이 어디 갔지?" 생각
  - 카페·배달음식 지출이 많음
  - 자산관리·투자보다 "이번 달 버티기"가 목표
- **니즈**:
  1. 지금 써도 되는 돈이 얼마인지 즉시 확인
  2. 복잡한 입력 없이 빠른 기록
  3. 죄책감을 느끼고 싶지 않음
- **사용 패턴**: 하루 3~6회 앱 실행, 대부분(3~5회)은 입력 없이 확인만 (회당 3초), 기록은 2~3회 (회당 10초)

## 3. 문제 정의

직장인 사용자의 핵심 관심사는 "이번 달 얼마나 남았지?"와 "오늘 얼마나 써도 되지?"인데, 기존 가계부는:

1. **질문에 답하지 않음** — 지출 기록과 사후 분석 중심이라 '남은 돈'이 한눈에 보이지 않음
2. **과도한 복잡성** — 계좌 연동·자산 관리 등 불필요한 기능으로 진입 장벽과 피로 유발
3. **감정 비용** — "지출이 너무 많아요" 같은 판단형 메시지로 죄책감·스트레스 유발

그 결과 사용자는 설치 → 며칠 사용 → 삭제 패턴을 반복하고, 소비 인식 자체를 포기한다.

## 4. 해결 방안

| # | 해결책 | 구현 |
|---|--------|------|
| 1 | **1초 확인** | 홈 히어로 영역에 '이번 달 쓸 수 있는 돈' + '남은 일수 · 하루 가용액' 즉시 표시. 로컬 IndexedDB라 로딩·오프라인 제약 없음 |
| 2 | **3터치 기록** | FAB → 금액+카테고리 → 저장. 시간대 기반 카테고리 추천, 날짜 '오늘' 기본값 등 스마트 기본값으로 평균 10초 내 기록 |
| 3 | **판단 없는 비춤** | 모든 문구는 중립적 사실 전달("예산의 80%를 사용했어요"). 예산 초과 시에도 빨간색·경고 없이 담담하게 표시 |
| 4 | **소비=관심 프레임** | 통계·월간리뷰·인사이트에서 "뭐에 관심이 많았는지"로 소비를 재해석 |
| 5 | **자동화·알림** | 반복거래 자동 실행(catch-up 포함), 예산·카테고리·반복거래·결제수단별 중립 톤 알림으로 기록 부담 최소화 |

---

## 5. 차별화 포인트

1. **프레임 전환**: 경쟁 가계부가 '지출 기록·절약'에 초점을 둘 때 PinPig는 '남은 돈 확인·인식'에 초점 — 확인 중심 앱
2. **감정 설계**: 판단·경고·빨간색을 배제한 중립 어조로 죄책감 없는 사용 경험 (금융앱이 아닌 일상앱)
3. **로컬 우선(local-first)**: 회원가입·서버·계좌연동 없이 IndexedDB에만 저장 — 개인 금융 데이터가 기기를 떠나지 않고 오프라인 완전 동작
4. **극단적 단순화**: 3터치 기록, 1초 확인. 투자·자산관리·또래비교·OCR은 의도적으로 범위 제외
5. **설치 장벽 없음**: PWA로 즉시 시작, 이후 Capacitor iOS 확장 가능한 구조

## 6. 사용자 시나리오 (요약)

> 상세 시나리오·감정 곡선은 [`docs/USER_JOURNEY.md`](../USER_JOURNEY.md) 참조

| 시나리오 | 흐름 | 소요 |
|----------|------|------|
| 첫 사용 | 온보딩에서 월 예산 하나만 설정 → 홈에서 즉시 남은 돈 확인 | 15초 |
| 출근길 확인 | 앱 열기 → "838,500원 · 15일 남음 · 하루 55,900원" 확인 → 닫기 | 3초 |
| 점심 기록 | FAB → 8,500 입력(점심시간이라 식비 자동 추천) → 저장 → 잔액 즉시 반영 | 10초 |
| 충동구매 순간 | 남은 돈만 확인, 앱은 판단하지 않고 결정은 사용자가 | 3초 |
| 급여일 | 수입 탭에서 급여 기록 → +기호·녹색 표시, 잔액 반영 | 10초 |
| 월말 리뷰 | 통계 탭에서 카테고리별 지출 + "식비에 가장 많이 썼어요" 중립 인사이트 | 1~2분 |

## 7. 성공 지표 (KPI)

| 지표 | 목표 | 측정 방법 |
|------|------|----------|
| 온보딩 완료율 | 90%+ | 예산 설정 완료 기준 |
| D1 리텐션 | 60%+ | 다음날 앱 열기 |
| D7 리텐션 | 40%+ | 7일 후 앱 열기 |
| 일평균 기록 | 2회+ | 거래 입력 횟수 |
| 기록 소요시간 | 15초 이내 | FAB → 저장 |

**정성 지표**: "복잡하지 않다" · "죄책감이 안 든다" · "확인용으로 좋다"는 사용자 반응
