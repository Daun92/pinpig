## 0. 데이터 모델 요약

> 원본: `src/types/index.ts`, 스키마: `src/services/database.ts` (Dexie/IndexedDB)

| 엔티티 | 핵심 필드 | 설명 |
|--------|----------|------|
| **Transaction** | type(income/expense), amount, categoryId, paymentMethodId?/incomeSourceId?, memo?, tags?[], date, time | 거래 1건. 지출은 결제수단, 수입은 수입수단 참조 |
| **Category** | name, icon(Lucide), color, type, budget?, order, isDefault | 지출 7종·수입 3종 기본 제공. budget으로 카테고리별 예산 |
| **PaymentMethod** | name, icon, color, order, isDefault, budget? | 지출 결제수단 (현금/카드/계좌이체 기본). budget으로 월 한도 |
| **IncomeSource** | name, icon, color, order, isDefault | 수입 수단 |
| **RecurringTransaction** | frequency(daily~yearly), dayOfMonth/dayOfWeek, startDate, endDate?, isActive, executionMode(on_date/start_of_month), nextExecutionDate, lastExecutedDate | 반복 거래 템플릿. 거래 필드(amount·category·수단·memo·tags) 복사 보유 |
| **AnnualExpensePattern** | categoryId, description, month, day, amount, year, isEnabled, notifyDaysBefore(기본 14) | 연 1회 지출(보험료·세금 등) 패턴 + 사전 알림 |
| **Settings** | monthlyBudget, startDayOfMonth, payday, theme, isOnboardingComplete, notificationEnabled + 알림 4종 설정, insightWidgets[], 코치마크 플래그 5종 | 단일 레코드 앱 설정 |

파생(계산) 타입: `BudgetStatus`(remaining·remainingDays·dailyRecommended·percentUsed·isOverBudget), `MonthlyBudgetStructure`(고정지출/가변예산/예상잔액), `ProjectedTransaction`(반복거래 기반 예상 거래), `MonthlyReview`, `BudgetRecommendation`(예산 마법사), 인사이트 상세 5종.

## R-01. 온보딩 및 첫 예산 설정 — `높음` `완료`

신규 사용자가 앱 최초 실행 시 복잡한 설정 없이 '이번 달 쓸 수 있는 돈' 하나만 입력하고 바로 홈으로 진입하는 첫 사용 경험 영역. 회원가입·로그인·계좌연동은 포함하지 않으며, 상세 예산 배분은 R-05에서 다룬다.

**인수 기준**
- [x] 최초 실행 시(`isOnboardingComplete=false`) 온보딩 화면이 표시되고 월 예산을 설정할 수 있다
- [x] 온보딩 완료까지 15초 이내, 예산 설정 외 필수 입력이 없다
- [x] 온보딩 완료 즉시 홈에서 남은 돈과 하루 가용액이 표시된다

| ID | 기능 | 정의 | 관련 |
|----|------|------|------|
| F-01-1 | 온보딩 게이트 | 설정의 `isOnboardingComplete`가 false면 라우터 진입 전 OnboardingPage만 렌더 | `App.tsx` |
| F-01-2 | 5단계 온보딩 | 웰컴 → 홈/기록/분석 기능 소개 3장 → 예산 설정. 프로그레스바 + 단계 점 인디케이터 | `OnboardingPage` |
| F-01-3 | 월 예산 설정 | 슬라이더(50만~500만, 5만 단위)로 지정, "나중에 설정에서 바꿀 수 있어요" 안내. "나중에 설정할게요"로 스킵 가능 | `OnboardingPage` |
| F-01-4 | 화면별 코치마크 투어 | 홈·입력·통계·설정·내역 첫 방문 시 1회 가이드 표시 (`hasSeen*Tour` 플래그) | `CoachMarkProvider` |

## R-02. 홈 대시보드 (1초 확인) — `높음` `완료`

사용자가 앱을 열자마자 추가 조작 없이 이번 달 남은 예산·남은 일수·하루 가용액을 확인하는 핵심 화면 영역. 인사이트 캐러셀, 최근 거래 목록, 거래 입력 진입점(FAB)을 포함한다. 상세 통계와 전체 내역은 각각 R-08, R-04에서 다룬다.

**인수 기준**
- [x] 앱 실행 후 로딩 대기 없이 남은 예산 금액이 히어로 영역에 표시된다
- [x] 남은 일수와 하루 가용액이 함께 표시된다
- [x] 예산 초과 시에도 빨간색·경고 없이 중립 문구로 표시된다
- [x] 최근 거래 목록과 FAB이 홈에서 바로 접근 가능하다

| ID | 기능 | 정의 | 관련 |
|----|------|------|------|
| F-02-1 | 남은 예산 히어로 | `BudgetStatus` 기반: 남은 금액, 프로그레스, "N일 남음 · 하루 M원". 초과 시 중립 문구 | `HomePage` |
| F-02-2 | 인사이트 캐러셀 | 선택된 위젯(최대 3개) 좌우 스와이프 표시 → R-09 | `InsightCard` |
| F-02-3 | 최근 거래 목록 | 최신 거래 일부 + '모두 보기' → `/history`. 빈 상태 안내 문구 | `HomePage` |
| F-02-4 | 반복거래 자동 실행 트리거 | 홈 마운트 시 `processRecurringTransactions()` 호출(밀린 거래 catch-up 최대 365건) → R-07 | `queries.ts` |
| F-02-5 | FAB (거래 입력 진입) | 플로팅 버튼 → `/add` | `TabBar`/`fabStore` |

## R-03. 거래 기록 및 수정 — `높음` `완료`

사용자가 지출·수입 거래를 3터치 이내로 기록하고, 기록된 거래를 상세 확인·수정·삭제하는 영역. 금액·카테고리·결제(수입)수단·날짜·시간·메모·태그 입력, 할부/반복 설정, 스마트 기본값을 포함한다. 반복거래 템플릿 관리 자체는 R-07에서 다룬다.

**인수 기준**
- [x] FAB → 금액+카테고리 → 저장의 3터치로 거래 기록이 완료된다
- [x] 저장 즉시 홈의 남은 예산에 반영된다
- [x] 거래 상세에서 모든 필드를 수정하거나 삭제할 수 있다
- [x] 할부 입력 시 분할 거래가 생성되고, 반복 설정 시 반복거래로 등록된다

| ID | 기능 | 정의 | 관련 |
|----|------|------|------|
| F-03-1 | 거래 입력 | 지출/수입 토글, 금액 키패드, 카테고리·수단 칩 선택, 날짜(기본 '오늘')·시간 | `/add` AddPage |
| F-03-2 | 스마트 기본값 | 시간대 기반 카테고리 추천(점심시간=식비 등), 마지막 사용 수단 유지 | AddPage |
| F-03-3 | 메모+태그 입력 | 한 입력창에서 태그·메모 파싱(`parseMemoWithTags`), 추천 태그 칩 | `utils/tags.ts` |
| F-03-4 | 할부/반복 3-way 토글 | 없음/할부/반복. 할부: 개월 수만큼 분할 거래 생성. 반복: 주기 선택 후 반복거래 등록(+다음 회차 미리 생성) | AddPage |

| F-03-6 | 거래 전체 수정 | 모든 필드 수정, 삭제. 기존 거래의 반복거래 전환 토글 포함 | `/transaction/:id/edit` |
| F-03-7 | iOS 단축어 딥링크 | URL 파라미터로 입력 화면 직행, 진입 시 포커스 처리 | `useDeepLink` |

## R-04. 거래 내역 조회 — `높음` `완료`

기록된 거래 전체를 월 단위·날짜별 그룹으로 탐색하는 영역. 일별 수입/지출 요약, 월 이동(미래 월 포함), 개별 거래 상세 진입을 포함한다. 집계·차트는 R-08에서 다룬다.

**인수 기준**
- [x] 거래가 날짜별로 그룹핑되어 표시되고 일별 수입/지출 요약을 확인할 수 있다
- [x] 월 단위로 이동하며 과거·미래 월의 내역을 조회할 수 있다
- [x] 내역 항목 탭 시 거래 상세로 진입한다

| ID | 기능 | 정의 | 관련 |
|----|------|------|------|
| F-04-1 | 날짜별 그룹 목록 | `DateGroup`/`MonthGroup` 기반, fixed header + sticky date 헤더, 월간 수입/지출/합계 요약 | `/history` |
| F-04-2 | 월 탐색 | ◀▶ 버튼 + 좌우 스와이프 월 이동 + 월 선택 모달(연도·4×3 그리드), 미래 월 허용 | HistoryPage |
| F-04-3 | 일별 요약 | 날짜 헤더에 해당 일 수입/지출 분리 표시 | HistoryPage |
| F-04-4 | 예상 거래 표시 | 반복거래 기반 `ProjectedTransaction`을 예정 항목으로 구분 표시 | R-07 연계 |
| F-04-5 | 검색·카테고리 필터 | 검색 아이콘 → 전체 기간 텍스트 검색(메모·태그 포함), 카테고리 다중 선택 필터 모달 + 초기화 | HistoryPage |
| F-04-6 | 맥락 스크롤 | URL `scrollTo=yesterday/future/today` 파라미터로 해당 그룹 자동 스크롤 (홈 하단 카드 연계) | HistoryPage |

## R-05. 예산 관리 — `높음` `완료`

월 총 예산과 카테고리별 예산을 설정·조정하는 영역. 설정 직접 입력, 지출 분석 기반 예산 마법사, 카테고리별 예산 일상 조정의 세 경로를 포함한다. 예산 대비 사용률 표시는 홈(R-02)·통계(R-08)·알림(R-10)에서 소비된다.

**인수 기준**
- [x] 설정에서 월 총 예산을 직접 입력·수정할 수 있다
- [x] 예산 마법사가 최근 3개월 지출 분석 기반으로 카테고리별 예산을 자동 배분 제안한다
- [x] 카테고리별 예산 페이지에서 개별 카테고리 예산을 조정할 수 있다

| ID | 기능 | 정의 | 관련 |
|----|------|------|------|
| F-05-1 | 월 예산 직접 입력 | 설정 화면에서 `monthlyBudget` 수정 (천단위 콤마) | SettingsPage |
| F-05-2 | 예산 마법사 | `BudgetRecommendation`: 3개월 평균/최대/최소 지출 분석 → 카테고리별 추천 예산 일괄 적용 | `/settings/budget-wizard` |
| F-05-3 | 카테고리별 예산 조정 | 카테고리 목록에서 예산 슬라이더/입력으로 조정, 총예산 대비 배분 표시 | `/settings/category-budget` |
| F-05-4 | 예산 구조 계산 | `MonthlyBudgetStructure`: 반복거래 기반 고정지출·예상수입 → 가변예산·예상잔액 산출 | `queries.ts` |

**인수 기준**
- [x] 카테고리를 추가·편집(이름/아이콘/색상)·삭제·정렬할 수 있고 기본 카테고리는 삭제가 방지된다
- [x] 결제수단과 수입수단을 탭으로 구분해 각각 관리할 수 있다
- [x] 변경된 분류가 거래 입력·수정·통계 화면에 즉시 반영된다

| ID | 기능 | 정의 | 관련 |

| F-06-1 | 카테고리 관리 | 목록·순서 변경·추가/삭제 (지출/수입 구분) | `/settings/categories` |

## R-07. 반복 거래 자동화 · 연간 지출 패턴 — `높음` `완료`

월세·구독료·급여처럼 주기적으로 발생하는 거래를 템플릿으로 등록하면 실행일에 자동으로 거래가 생성되는 영역. 주기 5종(daily/weekly/biweekly/monthly/yearly), 실행 모드 2종(당일 실행/월초 일괄), 밀린 거래 catch-up, 기존 거래의 반복 전환, 연 1회 지출 패턴(보험·세금) 관리를 포함한다. 실행 예정 알림은 R-10에서 다룬다.

**인수 기준**
- [x] 반복거래 템플릿 등록 시 실행일 도래 시 거래가 자동 생성된다
- [x] 앱 미접속으로 밀린 반복거래가 접속 시 일괄 생성(catch-up, 최대 365건)된다
- [x] 기존 일반 거래를 반복거래로 전환할 수 있다
- [x] 자동 생성된 거래에 "반복" 태그가 자동 부여된다

| ID | 기능 | 정의 | 관련 |
|----|------|------|------|
| F-07-1 | 반복거래 목록 | 활성/비활성 구분, 다음 실행일 표시 | `/settings/recurring` |
| F-07-2 | 반복거래 등록/편집 | 거래 필드 + 주기·시작/종료일·실행모드 설정. 등록 시 실행일이 오늘 이전이면 즉시 실행 + 다음 회차 미리 생성 | `/settings/recurring/new`, `:id/edit` |
| F-07-3 | 자동 실행 엔진 | 홈 마운트 시 `nextExecutionDate ≤ today`인 활성 템플릿 실행, 다음 실행일 재계산 | `processRecurringTransactions()` |
| F-07-4 | "반복" 태그 자동 부여 | 모든 등록 경로(AddPage/전환/템플릿)에서 태그 자동 추가 | 공통 |
| F-07-5 | 연간 지출 패턴 | `AnnualExpensePattern` 등록(설명·발생 월일·작년 금액)·알림 토글·N일 전 알림(기본 14일). 작년 거래 데이터 스캔으로 큰 지출 자동 감지 → "알림 추가" | `/settings/annual-expenses` |

## R-08. 통계 및 리포트 — `높음` `완료`

월별 지출·수입을 카테고리·결제수단 기준으로 확인하고 기간별 추이를 탐색하는 분석 영역. 분석 탭(도넛 차트·리스트·예산 대비 %), 항목별 추이 모달, 월간 리뷰를 포함한다. 문구는 중립 톤을 유지하며 절약 권고·판단형 메시지는 배제한다.

**인수 기준**
- [x] 월별 카테고리·결제수단별 지출 분포를 도넛 차트와 리스트로 확인할 수 있다
- [x] 카테고리·수단 리스트에 예산/한도 대비 사용률(%)이 표시된다
- [x] 항목 탭 시 월별 추이 모달이 열린다
- [x] 월간 리뷰에서 한 달 소비를 중립 톤 인사이트로 회고할 수 있다

| ID | 기능 | 정의 | 관련 |
|----|------|------|------|
| F-08-1 | 월 요약 | 해당 월 지출 총액, 예산 대비 %, 월 이동 | `/stats` |
| F-08-2 | 카테고리 분석 | 도넛 차트(`CategoryDonutChart`) + 리스트(금액·비중·건수·예산%) | StatsPage |
| F-08-3 | 결제수단 분석 | 도넛 차트(`PaymentMethodDonutChart`) + 리스트(한도 대비 %) | StatsPage |
| F-08-4 | 추이 모달 | 카테고리/수단별 월별 추이 차트 (`*TrendModal`) | StatsPage |
| F-08-5 | 기간별 추이 탭 | 기간 선택(6개월/12개월/연간) + 카테고리 필터(최대 3개) + 멀티 라인 추이 차트 | StatsPage |
| F-08-6 | 지출/수입 모드 · 월간/연간 전환 | 상단 지출/수입 탭 + 월간/연간 토글, 수입 모드에선 저축률 표시 | StatsPage |
| F-08-7 | 월간 리뷰 | `MonthlyReview`: 총지출·예산사용률·발견한 점(`ReviewInsight`)·전월 카테고리 비교, "유지하기/조정하기" 액션 | `/review` |

## R-09. 홈 인사이트 — `중간` `완료`

홈 상단 캐러셀에서 소비 패턴을 중립적 문구로 비춰주는 인사이트 카드 영역. 6종 위젯, 표시 카드 선택 설정(최대 3개), 카드 탭 시 URL 파라미터 기반 상세 화면 이동을 포함한다. 판단·권고형 문구는 배제한다.

**인수 기준**
- [x] 홈 캐러셀에서 인사이트 카드를 좌우 스와이프로 탐색할 수 있다
- [x] 인사이트 설정에서 표시할 카드를 최대 3개 선택·저장할 수 있다
- [x] 카드 탭 시 관련 상세 화면으로 맥락(insight/categoryId/month)이 전달되며 이동한다

| ID | 기능 | 정의 | 관련 |
|----|------|------|------|
| F-09-1 | 인사이트 위젯 6종 | caution(예산 70%+), room(예산 <50%), compare(전월 대비), interest(TOP 카테고리), upcoming(예정 거래), budget-overview(예산 배분 현황) | `INSIGHT_WIDGET_CONFIG` |
| F-09-2 | 위젯 데이터 조건 | 카테고리 예산/전월 데이터/예정 거래 유무에 따라 표시 가능 여부 판단 | 동상 |
| F-09-3 | 인사이트 설정 | 위젯 선택(최대 3개) + FAB 저장 UI | `/settings/insights` |
| F-09-4 | 상세 뷰 연결 | `InsightParams`(insight·categoryId·month) URL 파라미터로 통계/내역에 맥락 전달 | 공통 |

## R-10. 알림 시스템 — `중간` `완료`

예산 사용률·반복거래 예정 등 사용자가 알아야 할 정보를 앱 내 토스트로 중립 톤 전달하는 영역. 마스터 토글 아래 전체 예산·카테고리별·반복거래·결제수단별 4종 알림과 각 설정 페이지를 포함한다. OS 푸시 알림은 Phase 2 범위로 제외한다.

**인수 기준**
- [x] 마스터 토글 OFF 시 모든 하위 알림이 비활성화되고 설정 UI가 숨겨진다
- [x] 월 예산·카테고리 예산 사용률이 임계값 도달 시 토스트가 표시된다 (월 1회 중복 방지)
- [x] 반복거래 실행 N일 전 사전 알림이 표시되고 거래별로 시점을 조정할 수 있다
- [x] 결제수단별 한도 임계값 도달 시 거래 저장 직후 토스트가 표시된다

| ID | 기능 | 정의 | 기본 임계값 |
|----|------|------|------------|
| F-10-1 | 알림 마스터 토글 | `notificationEnabled` — 전체 on/off | ON |
| F-10-2 | 전체 예산 알림 | 월 예산 사용률 임계 도달 시 토스트, `lastAlerted*`로 중복 방지 | [50, 80, 100]% |
| F-10-3 | 카테고리별 알림 | 카테고리 예산 대비, 카테고리별 개별 on/off·임계값. 카테고리 편집과 연계 | [70, 100]% |
| F-10-4 | 반복거래 알림 | 실행 N일 전 사전 알림, 전역 기본(`recurringAlertDaysBefore`=1) + 거래별 오버라이드 | 1일 전 |
| F-10-5 | 결제수단별 알림 | 수단 한도(budget) 대비, 거래 저장 직후 즉시 확인 | [70, 100]% |
| F-10-6 | 알림 설정 페이지 4종 | budget-alerts / category-alerts / recurring-alerts / payment-method-alerts | — |
| F-10-7 | 토스트 표시 | 타입별 tinted 배경(다크모드 차별화), `ToastContainer` 공통 렌더 | — |
